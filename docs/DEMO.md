# GIF 演示说明

`assets/demo.gif` 为 1200 × 760、25.8 秒的流程动画，展示实际执行插件核心后得到的结果。它是排版回放，不是 Harness 界面录屏。

## 数据来源

在独立 Git 仓库写入 `examples/test-cases/case-1-race-condition/before.ts`，调用真实的 `ReviewService.startReview()`；将文件替换为 `after.ts`，再调用 `recheck()`。第三次不修改源码，再次调用 `recheck()`。

审查和复查使用本地确定性脚本模型，预置候选与核查回复。Git 快照、两轮调度、代码引用核对、编号保持、状态更新、存储和跳过重复调用均由插件代码实际执行。预置回复不能证明真实模型能发现该问题。

本次执行结果：

| 项目 | 实际结果 |
|---|---|
| 首轮问题 | `ISS-001`，`open` |
| 修复后复查 | 同一编号，`resolved` |
| 总审查轮次 | 2 |
| 模型调用次数 | 4 |
| 源码未变化时新增模型调用 | 0 |

并发结果另行运行示例真实代码，控制执行顺序：v3 构建暂停，v4 发布，v3 恢复。修复前最终为 v3；启用条件发布后最终为 v4。示例 Store 实现原子的条件比较，并隔离版本数据；实际系统也必须满足该前提。

动画持续显示“本地脚本模型”，并标注“非 DeepSeek 检出效果评测”。播放时长是为阅读安排的时间，不代表模型延迟。
