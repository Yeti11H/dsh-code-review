# Codex 宿主模型审查适配

目标：让 Codex 当前会话分析代码，不启动子模型或使用 DeepSeek API；保留现有快照、引用校验和报告能力。用户已选择该方案并要求实现。仅本地实现与安装，不提交或发布。

方案比较：CLI 包装最省事但仍依赖独立 API；MCP 接入适合多宿主但引入服务生命周期；本轮选择 Skill 加离线脚本，复用确定性核心。

## 接口与边界

- `prepare` 固定 Git 快照及需求上下文，写入待扫描输入与未完成报告。
- Codex 读取分批 diff，使用 `context` 读取冻结文件，提交带会话、代码及上下文哈希的扫描 JSON。
- `scan` 校验候选位置、数量和覆盖声明，生成候选核查输入。未发现也必须明确提交空数组。
- Codex 核查每个候选并提交核查 JSON；`finish` 检查候选一一对应，复用逐字引用校验。格式错误可修正重交，不能成为无问题结论。
- 每次提交和状态查询检查当前快照。代码变化后标记过期，不接受旧结果。需求变更须新建审查。
- `status` 显示阶段和未完成原因；`cancel` 明确终止。进程中断保持待处理状态。
- 报告沿用 JSON/Markdown，增加 Codex 分析来源和局限说明。引用不匹配降级待核查；无覆盖或有遗漏需人工。
- 不执行被审仓库脚本、不改源文件、不自动批准，不采信模型声称的测试执行。无网络请求和 API key。
- 首版只有首次审查，不冒充 DSH 的增量复查、三轮收敛和问题处置。两轮来自同一上下文，不声称独立核查。
- Node >=24.9、Git 已有提交。自包含 Skill 发布目录不依赖本地源码路径、node_modules 或 DSH。

## 验收

独立临时 Git 仓库覆盖正常缺陷、无发现、错误引用、业务缺失、候选遗漏、错误绑定、覆盖缺失、过期、取消、畸形输入和仓库子目录。实际运行独立 Skill 命令、Skill 校验、现有回归与打包检查。模型生成结果和确定性测试严格区分；未经真实 Codex 操作的行为不称实测。
