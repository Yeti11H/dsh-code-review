# 本地交付验收

本记录对应 `dsh-code-review` 0.1.0 核心实现的本地验收。0.1.1 仅调整分发与文档，增加 GIF；发布状态以 GitHub Release 和 npm 作用域包 `@ooohyg/dsh-code-review` 为准。

## 环境与兼容版本

- Windows，Node.js 24.16.0，Git 2.51.0.windows.1。
- DeepSeek Harness 0.2.2-rc.1。
- 官方 `@deepseek-ai/cordis` 4.1.0、`@deepseek-ai/dsh-tools` 与 `@deepseek-ai/dsh-llm` 0.2.2-rc.1。
- 固定上述 Harness 版本，不承诺自动兼容后续版本。

## 自动化验证

- `npm run typecheck`：通过。
- `npm test`：40 项，39 项通过，0 项失败，1 项跳过。
- 跳过项：Windows 环境创建符号链接返回 `EPERM`；符号链接场景需要在有相应权限的环境补验。
- Git 测试使用真实临时仓库，覆盖暂存、未暂存、未跟踪、分支、重命名、删除、Unicode、读取上限和分批。
- 审查测试覆盖两轮流程、引用校验、误报反证、缺少业务信息、稳定编号、修复与重现、增量复查、三轮收敛、过期快照、取消、超时、错误恢复和存储锁。
- 并发案例运行真实代码，通过控制暂停点复现旧版本覆盖新版本，并验证条件发布后保留新版本。
- 官方 Cordis、工具服务、LLM 服务与工具执行管线实际装配，验证四个工具注册、参数校验、两轮调用和批准缺失时拒绝执行。

## 官方 Web 加载

使用独立 `DSH_HOME` 和本地绝对路径 overlay 启动：

```sh
npx @deepseek-ai/dsh@0.2.2-rc.1 web --patch <overlay.yml> --no-open --host 127.0.0.1 --port 3097
```

服务启动成功；配置转储包含插件；带本地会话认证访问首页返回 HTTP 200。没有在该 Web 会话中调用真实模型审查。运行时集成测试另行验证工具调用流程。

## 安装包与案例准备

- `npm pack` 生成本地 `.tgz`，检查归档不包含依赖目录、工作文件、用户配置或密钥。
- 在独立目录中通过 `npm install <本地安装包>` 安装成功；从安装后的包导入插件与核心模块，并在官方运行时注册四个工具。
- 安装包内的加载脚本成功生成目标仓库 overlay。
- 案例准备脚本成功创建并提交三个独立 Git 仓库，再写入待审改动。
- 源码 ZIP 包含源码、编译产物、测试、锁文件、文档和案例，不包含 `node_modules` 与本地工作目录。

## 证据的边界

上述模型调用使用确定性的本地测试适配器。这能验证程序如何处理模型结果，不能证明 DeepSeek 能检出已知缺陷，也不能测量误报率、召回率、延迟或费用。

真实模型验收仍需使用者在 Harness 中配置可用模型，按 `examples/live-evaluation.md` 执行案例并保存结果。两个阶段使用同一底层模型，并非独立人工复核。引用校验只检查引用真实性，不能证明推理正确。

原方案中的“杜绝幻觉”“第一个插件”等宣传结论未作验收承诺。第一版使用文本和导入关系补充上下文，没有完整 AST 或跨语言调用图。
