# 0.2.0 改进设计

本轮依据用户提供的改进清单推进，保留现有审查核心。目标分为六项：README、非交互 CI、风险排序、自定义规则、反馈记忆、真实 Web 演示。实现与验证完成后再更新公开源码和试用包；社区发帖、官方贡献和视频平台上传只准备文稿，不自动外发。

## 具体取舍

1. README 先说明价值、安装与已测边界。竞品比较只比较可验证的流程，不推断 Copilot 的实现或误报率。明确本地插件仍会向选定模型发送代码。
2. CI 脚本复用 ReviewService，参数包含 target、requirement、business-rules、output-json、exit-code；密钥只从环境变量读取。确认缺陷可退出 1，失败退出 2，待核查默认不冒充确认缺陷。示例只上传报告 artifact，不执行仓库脚本、不写 PR 评论、不向 fork PR 暴露密钥。
3. 风险分为 0–10 的启发式处理优先级，非缺陷概率或经过校准的 PR 风险。已解决为 0；总分取未处理问题最大值，避免低风险项稀释高风险项。建议仅为 request_changes、needs_human_review、no_findings，不批准合并。保持旧 JSON 会话兼容。
4. 自定义规则使用安装者提供的正则，在隔离 worker 中限时扫描新增行。命中是检查线索，单独展示并送模型核查，不能自动证明注入、缺少事务或鉴权。限制规则、扫描和匹配数量，超限明确标记覆盖不足。
5. 反馈记忆仅来自使用者明确标记的 false_positive 和 wont_fix，附原因。按同仓库、同业务上下文、同文件及仍存在的原文片段匹配；仅作为反证提示，不自动屏蔽未来风险。reopen 移除对应记忆。单线程不能证明异步竞态不存在，不采用清单中的错误示例。
6. 尝试实际启动官方 Web，通过浏览器记录选择模型、请求工具和阅读报告。若使用脚本模型或重放必须持续标明，绝不将排版动画伪装成真实 UI。实际模型调用以少量案例为限，记录用量；密钥不进入视频、配置或源码。

## 验证

对 CI 参数、实际 CLI 退出码/产物、报告风险、不确定性状态、规则限时/范围、反馈的匹配和失效补充测试。执行既有测试、类型检查、归档检查和干净安装。真实 GitHub 托管 runner、真实模型复测和 Web 录屏分别列明证据，未完成项不能冒称通过。
